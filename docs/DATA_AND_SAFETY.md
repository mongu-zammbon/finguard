# 데이터 및 안전 경계

## 입력 데이터

현재 데모는 외부 데이터 수집 없이 사용자가 공유한 텍스트, 로컬에서 선택한 스크린샷 미리보기, 코드에 포함된 회의용 예시만 사용한다. 실제 개인정보·계좌번호·인증번호를 넣지 않는다. 스크린샷 자체는 서버로 업로드하지 않으며, 텍스트 분석은 사용자가 입력한 OCR 결과 fallback으로 수행한다.

## 처리 원칙

- 텍스트는 요청 처리 중 메모리에서만 사용한다.
- 응답은 `Cache-Control: no-store`를 사용한다.
- 서버 로그는 HTTP method와 path만 남기며 query string과 원문을 남기지 않는다.
- 결과의 evidence는 향후 확장 시 전화번호·금융번호·식별번호 마스킹을 거친다.
- 외부 URL fetch, 제3자 LLM 호출, 금융 API 호출은 없다.
- 이미지 파일은 브라우저 object URL로만 미리 보고 페이지 종료·경로 전환 시 해제한다.
- `결제 링크` 모드는 URL을 열거나 DNS 조회하지 않고, 링크가 들어 있는 메시지 텍스트만 분석한다.

## 안전한 라벨 의미

`DANGER`는 사기 확정이 아니라 즉시 행동 중단 신호다. `LOW_RISK_NOT_PROOF`는 안전 판정이 아니며, `ABSTAIN`은 모델이 충분히 판단하지 못해 사람 확인으로 전환하는 신호다.

## 운영 전환 조건

운영 서비스로 바꾸기 전에는 최소한 다음을 추가한다.

1. 개인정보 자동 탐지·마스킹과 보존 정책
2. 공개 사례와 정상 대화가 분리된 시간축 평가셋
3. 라벨별 precision/recall, 위험 케이스 recall, abstain rate
4. 사람 검토 큐와 오탐 이의제기 경로
5. 외부 연동을 허용할 경우 URL allowlist, rate limit, 감사 로그, 인증
