# 오늘 미팅 데모 대본

목표 시간: 90초~2분. 발표자는 기능을 설명하기보다 화면에서 사용자의 행동 변화를 보여준다.

## 0. 오프닝 — 10초

“사기 탐지는 거래가 일어난 뒤에도 가능합니다. FinGuard는 사용자가 송금·인증·클릭하기 직전, 대화문을 붙여 넣는 30초를 지킵니다.”

## 1. DANGER — 25초

`기관 사칭 + 안전계좌 이체` 버튼을 누른다.

확인할 화면:

- `DANGER`
- “송금·인증·링크 클릭을 중단”
- `금융감독원`, `지금`, `안전계좌`, `이체` 근거 칩

멘트: “단어 하나가 아니라 기관 사칭·긴급성·이체 요구가 한 화면에서 연결됩니다.”

## 2. INJECTION — 20초

`분석기를 흔드는 지시문` 버튼을 누른다.

멘트: “금융 대화 안에 분석기를 속이는 지시가 섞여도, 입력의 지시문을 따라가지 않고 격리합니다. 이것은 금융 사기 신호와 AI 공격 신호를 같은 안전 게이트에서 다루는 장면입니다.”

## 3. 정상/비증명 — 15초

`일반 공지처럼 보이는 메시지` 버튼을 누른다.

멘트: “모든 문자를 사기로 몰지 않습니다. 위험 신호가 낮아도 `LOW_RISK_NOT_PROOF`라고 표시해 안전 확정을 거부합니다.”

## 4. 즉석 질문 — 20초

팀원에게 “첫 사용자는 누구로 할까요? 가족에게 온 의심 문자 사용자와 상담원 중 누구를 먼저 잡을까요?”라고 묻고, 한 문장을 직접 입력받는다.

정상적인 최종 행동은 “공식 앱/대표번호에서 독립 확인”이다. 실제 송금, 로그인, URL 방문을 시연하지 않는다.

## 회의에서 결정할 5개

1. 첫 사용자는 개인 사용자 vs 상담원 중 누구인가?
2. 첫 wedge는 보이스피싱/기관 사칭 vs 투자 사기 중 무엇인가?
3. 결과 화면에서 가장 먼저 보여줄 한 문장은 무엇인가?
4. `ABSTAIN`을 사람 검토 큐로 확장할 것인가?
5. 내일 확보할 공개 사례와 평가셋의 담당자는 누구인가?
