# FinGuard 서비스 브리프

## 서비스 정의와 핵심 검증 질문

FinGuard를 “금융 전반을 상담하는 AI”가 아니라, **금융사고 전후의 자료를 한 사건으로 연결하고 다음 공식 행동을 안내하는 안전 게이트**로 정의한다. MVP의 주인공은 계좌가 막힌 후의 FROZEN 소명 준비이며, BEFORE·AFTER·SHIELD는 같은 기록 구조로 이어지는 진입점이다.

현재 우선 검증은 FROZEN의 ‘원문 → 사용자 확인·수정 → 상충 표시 → 소명팩’이 실제로 이어지는지입니다. 아래 행동 직전 관련 가설은 BEFORE의 초기 검증 가설로 유지합니다.

1. 첫 사용자는 누구인가?
2. 어떤 행동 직전에 가장 강한가?
3. 어떤 문장과 결과를 보면 사용자가 실제로 멈추는가?

## 첫 사용자와 사용 순간

- 첫 사용자 가설: 금융 사기 문자를 받은 사람과, 원문을 대신 확인해주는 가족·보호자
- 개입 시점: 송금·인증·링크 클릭 직전 30초
- 첫 wedge 후보: 보이스피싱·기관 사칭을 기본값으로 두고, 중고거래 결제 링크를 행동 실험용 비교군으로 둔다.
- 제품 진입: 문자·메신저 공유, 화면 스크린샷, 결제 링크가 포함된 메시지. 직접 붙여넣기는 모든 경로의 텍스트 fallback이다.

## 사용자 경험

```text
BEFORE  입력 → 빠른 점검 결과 / 공식 확인
AFTER   송금 직후 → 72시간 초기 대응 안내
FROZEN  원문 수집 → 사용자 검토 → 소명팩
SHIELD  연락 기록 → 원문 확인 → 상담 준비 자료
```

각 서비스는 자체 목적에서 완료할 수 있습니다. 모든 사용자를 FROZEN으로 보내는 필수 흐름은 아닙니다. 홈의 서비스 설명과 기존 구성은 유지합니다. SHIELD에서 계좌도 막힌 경우에만 FROZEN 진입을 선택할 수 있으며, 원문을 자동 공유하거나 사건을 합치지는 않습니다.

BEFORE의 입력은 SMS·메신저·화면 캡처에서 들어온 내용입니다. 현재 로컬 데모는 직접 입력한 텍스트를 규칙으로 점검하고 스크린샷은 미리보기만 합니다. FROZEN·SHIELD의 사건 작업은 원문을 문장 단위로 정리하고, 사용자가 확인한 내용과 수정 이력을 분리합니다. AI가 사실·위법성을 자동 확정하거나 이미지/PDF에서 값을 추출하는 기능은 아직 없습니다. 외부 입력 URL은 열지 않습니다. 출력은 사람이 확인할 근거와 다음 행동입니다.

## 첫 wedge

**보이스피싱·기관 사칭·원격제어·안전계좌 이체 요구**가 섞인 대화다. 거래 후 탐지보다 사용자가 행동하기 전의 30초를 공략한다.

## 경쟁 대안과 승부처

| 대안 | 사용자가 얻는 것 | FinGuard가 겨냥하는 빈틈 |
|---|---|---|
| 금융사 사기탐지 | 계좌·거래·디바이스 기반 사후/기관 탐지 | 기관이 볼 수 없는 대화 원문과 행동 직전 판단 |
| 검색 | 비슷한 사례와 링크 | 확인 편향을 줄이는 단일 판정·근거·다음 행동 |
| 지인에게 질문 | 정성적인 제3자 의견 | 5초 안에 반복 가능한 안전 체크 |
| 키워드 경고 | 단어가 포함됐다는 신호 | 사칭·긴급성·비밀 요구·이체의 결합과 보류/확인 UX |

## 데모 계약

- 첫 화면에서 “행동하기 전에 한 번 멈춰보세요”를 전달한다.
- 위험 케이스는 `DANGER`와 함께 “송금·인증·링크 클릭 중단 → 공식 앱/대표번호 확인”을 보여준다.
- 프롬프트 공격 케이스는 `INJECTION`과 “입력 안의 지시문을 따르지 말 것”을 보여준다.
- 정상 공지 케이스는 `LOW_RISK_NOT_PROOF`로 내려가 “낮은 위험 = 안전 증명 아님”을 보여준다.

## MVP와 다음 단계

### 현재 구현된 MVP

- Python 3.12 표준 라이브러리 단일 서버
- BEFORE·AFTER·FROZEN·SHIELD의 세로 진입 구조와 브라우저 입력창
- 로컬 스크린샷 미리보기 + OCR 텍스트 fallback
- 데모 케이스, 결과 패널, 행동 체크리스트
- 설명 가능한 규칙 엔진
- 라벨·위험 점수·근거·안전 행동·면책 문구
- FROZEN C01–C08 사건 워크스페이스와 원본·사실·거래·이슈·타임라인·보고서 흐름
- SHIELD의 독립적인 연락 입력·원문 검토·자료 선택·이슈·타임라인·상담 준비 업무
- 합성 텍스트/TXT 입력, 원문 보존, 문장별 사용자 확인·수정·메모·변경 이력
- 같은 명시 주문 ID의 금액 상충 표시, 근거 원문 연결, 선택한 내용의 HTML 소명팩/상담 준비 자료
- 새 사건과 이전 사건의 분리·전환, 내보내기 제외 자료와 연결 이력의 누출 방지
- 로컬 전용 실행과 no-store 응답

현재 사건은 탭 메모리에만 존재합니다. 새로고침·종료 전 내려받아야 하며, HTML 보고서는 재편집 가능한 전체 사건 백업이 아닙니다. 서버 저장·자동 기관 접수·24시간 보관 후 삭제는 미구현입니다. 기존 상세 설계 화면은 삭제하지 않고 예시로 보존합니다.

### 다음 검증 단계

- 공개 접속 가능한 제출 URL과 정해진 접근 기간 검증(로컬 주소는 제출 URL이 아님)
- FROZEN 실제 원문 추출 정확도·사용자 수정률·소명팩 준비 시간 검증
- 저장·복구를 도입하기 전 동의·암호화·접근 통제·삭제 정책의 구현과 테스트
- 실제 공개 사례 기반의 익명 텍스트 평가셋 구축
- 라벨별 precision/recall, 위험 케이스 recall, abstain rate 측정
- 규칙 엔진과 소형 분류 모델의 오프라인 비교
- 사람이 읽고 행동을 멈추는지에 대한 사용자 테스트

## 비범위

잔고 조회, 송금 실행, 계좌 확인, URL 방문, 금융기관 로그인, 개인별 투자 조언, 안전 확정 문구는 이번 MVP에서 만들지 않는다.
