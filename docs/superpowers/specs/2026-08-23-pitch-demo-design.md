# FinGuard 발표 모드·데모 강화 설계

## 목적

오늘 팀 미팅에서 친구의 아이디어와 FinGuard를 같은 기준으로 비교하고, 현재의 얇은 MVP를 “문자·스크린샷·결제 링크 공유 뒤 행동 직전의 30초를 지키는 금융 안전 게이트”라는 서비스 경험으로 보여준다. Google Slides는 백업 자료로 유지하고, 로컬 HTML 발표 모드를 주 발표 도구로 제공한다.

## 사용자와 발표 상황

- 사용자: 오늘 회의에 참여하는 팀원과 아이디어를 제안하는 친구
- 발표자: 팀 구성원 누구나
- 환경: 인터넷 없이도 실행 가능한 로컬 Python 서버와 브라우저
- 발표 시간: 90초 기본 데모, 이후 자유 입력과 아이디어 비교
- 기술 제약: Python 3.12 이상, 외부 패키지 추가 없음, 원문 로그·외부 URL fetch 없음
- 첫 타깃 가설: 금융 사기 문자를 받은 사람과 대신 확인하는 가족·보호자
- 첫 행동 순간: 송금·인증·링크 클릭 직전 30초
- 첫 진입 경로: 공유받은 문자, 스크린샷, 결제 링크; 붙여넣기는 텍스트 fallback

## 정보 구조

### `/pitch` 발표 모드

한 페이지를 세로로 스크롤하는 발표형 화면으로 만든다.

1. **THESIS** — “행동하기 전에, 한 번 멈춰보세요.”
2. **MOMENT** — 대화 수신 → 공유 → 송금·인증·클릭 → 피해
3. **SERVICE** — 공유·스크린샷·링크 → 위험 근거 → 안전 행동
4. **LIVE DEMO** — 6개 사전 케이스를 선택하고 결과를 즉시 확인
5. **TRUST** — 라벨·근거·하지 말 것·지금 할 것·ABSTAIN
6. **COMPETITION** — 금융사 탐지·검색·지인 질문 대비 빈틈
7. **EXPANSION** — 규칙 데모 → 한국어 분류 모델 + 전술 추출 + 정책 레이어 + 공개 URL
8. **DECISION** — 첫 사용자, 첫 wedge, 평가셋 오너, 다음 실험

각 섹션은 발표자의 말보다 화면의 문장과 실제 결과가 먼저 읽히도록 구성한다. 친구의 아이디어는 마지막 결정 섹션에서 동일한 평가 기준으로 비교한다.

## 서비스 데모 UX

### 실제 사용 진입

일반 서비스 화면은 첫 화면에서 타깃과 사용 순간을 설명하고, `공유받은 문자`를 기본으로 선택한다. `스크린샷`은 이미지 파일을 브라우저 안에서만 미리 보며 현재 규칙 엔진에는 OCR 결과 텍스트를 별도로 입력한다. `결제 링크`는 URL을 열지 않고 메시지 문맥만 분석한다. 세 모드 모두 최종 요청은 기존 `POST /v1/analyze`의 텍스트 계약을 재사용한다.

### 케이스

서버의 `/v1/demo-cases`는 다음 6개를 제공한다.

| id | label | 장면 |
|---|---|---|
| danger-transfer | DANGER | 기관 사칭 + 안전계좌 이체 |
| danger-remote | DANGER | 원격제어·화면 공유 요구 |
| danger-investment | DANGER 또는 CAUTION | 확정 수익·투자금 요구 |
| danger-marketplace | DANGER 또는 CAUTION | 중고거래 안전결제·링크 유도 |
| prompt-injection | INJECTION | 분석기 우회·비밀정보 출력 지시 |
| low-risk-not-proof | LOW_RISK_NOT_PROOF | 정상처럼 보이나 안전 확정 불가 |

케이스의 `label`은 기대 결과이며 실제 분석 결과와 일치해야 한다. 결과가 다르면 UI가 기대값을 숨기고 관찰 결과를 우선 표시한다.

### 결과 카드

결과 영역에는 다음 순서가 고정된다.

1. 결과 라벨과 한 줄 제목
2. 위험·프롬프트 공격·신뢰도 수치
3. “지금 할 행동” callout
4. 입력 안에서 발견된 근거 chip
5. 탐지된 패턴
6. `LOW_RISK_NOT_PROOF` 또는 `ABSTAIN`의 의미
7. 데모 면책 문구

색상만으로 상태를 전달하지 않는다. 라벨 텍스트와 행동 문장을 항상 함께 노출한다.

## 발표 모드 인터랙션

- `Space` 또는 화면의 “90초 데모 시작” 버튼은 API가 제공하는 6개 케이스를 순서대로 선택한다. 시간이 짧으면 발표자는 DANGER → INJECTION → LOW_RISK_NOT_PROOF 세 장면만 말로 강조한다.
- `Escape`는 자동 진행을 멈춘다.
- 케이스 버튼은 `<button>` 요소를 사용하고, 키보드 포커스를 표시한다.
- 자동 진행은 입력값을 서버에 저장하지 않는다.
- 서버 요청 실패 시 빈 화면 대신 “데모 서버를 실행해 주세요” 상태를 보여준다.

## 확장 아키텍처 메시지

발표 모드에 기술 구현 상세 대신 다음 서비스 확장 구조만 보여준다.

```text
대화/스크린샷 입력
        ↓
정규화·민감정보 보호
        ↓
사기 전술·행동 분류 모델
        + 설명 가능한 규칙
        ↓
위험 보정·ABSTAIN 정책
        ↓
근거 + 중단 행동 + 공식 확인 체크리스트
```

현재 코드는 첫 번째 규칙 기반 thin slice다. 최종 대회 버전은 공개 사례·정상 대화·애매한 입력·공격 입력을 시간축으로 분리한 평가셋에서 모델과 정책을 검증한 뒤 배포한다.

## 비범위

- 실제 송금·로그인·계좌 조회
- 외부 URL 방문 또는 검색
- 친구 아이디어를 자동으로 승패 판정하는 기능
- 규칙 데모를 최종 AI 성능으로 포장하는 기능

## 완료 기준

- `/pitch`가 로컬 서버에서 새로고침 없이 동작한다.
- 발표 모드에서 6개 케이스와 90초 흐름을 직접 시연할 수 있다.
- 모바일·노트북 화면에서 가로 스크롤 없이 읽힌다.
- 브라우저 콘솔에 오류·경고가 없다.
- 기존 `/` 데모의 DANGER·INJECTION·LOW_RISK_NOT_PROOF 동작이 유지된다.
- Google Slides에 MVP 한계·우승 확장·오늘의 결정이 반영된다.
